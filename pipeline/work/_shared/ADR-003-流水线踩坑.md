# ADR-003：管理端 gate / deploy / accept 踩坑（2026-08-15）

| 项 | 内容 |
|----|------|
| 状态 | 已落地 |
| 范围 | `bin/gate.py`、`bin/deploy.py`、`bin/accept.py`、`bin/notify.py`、92/93 Dockerfile 与 compose |
| 触发 | 用户线路权限查询闭环 |

## 决策

流水线入口只用 Python，不再提供 `gate.bat` / `deploy.bat` / `accept.bat` / `notify-dingtalk.bat`。这样既避开 Windows `CALL` 连字符解析和批处理延迟展开，也方便后续跨平台。Docker 匿名卷挡 jar、Playwright 点到隐藏节点、钉钉 token 误填整段 URL 仍按下面处理。根因写进脚本和 compose，不靠下次人工记得。

## 问题与处理

| 问题 | 根因 | 处理 |
|------|------|------|
| `gate.bat server` 前端已编过仍报失败 | `if (...)` 里 `%UI_ERR%` 解析时为空 | 已废止 bat 入口，改 `python bin/gate.py` |
| `deploy.bat` 无限递归 | `CALL deploy-admin-92.bat` 被当成再跑 `deploy.bat` | 已废止 bat 入口，改 `python bin/deploy.py` |
| 部署后接口 404 | Dockerfile `VOLUME /home/ruoyi` 匿名卷挡住新 jar | 去掉该 VOLUME；compose 绑定宿主机 jar；deploy 仍 `docker cp`+校验 MD5+等 `Started` |
| 点不到「查看权限」 | Element UI 下拉在表内留隐藏副本 | 只点可见节点，并轮询等待 |
| accept 误报通过 | toast「加载线路权限失败」含「线路权限」 | 点过按钮后断言弹窗标题 |
| 同日报告被覆盖 | 脚本每次重写 `验收报告-YYYY-MM-DD.md` | 改为追加 |
| 失败未自动钉钉 | 只手工调 notify | accept 结束自动发（无凭证则跳过） |
| 钉钉 `token is not exist` | `access_token` 填了整段 webhook | `local_env` 拆 URL；example 注明只填 token 段 |
| 菜单 1085/1086 插不进去 | 已被同步任务占用 | 改 1087/1088；91 用 `bin/apply_sql_91.py` |
| deploy 长时间无输出 | Python 重定向块缓冲 | `python -u` + line buffering |
| `ruoyi-gateway` 已 Up 仍报 120s 未 Started | 启动后 DEBUG 路由刷新刷屏，`wait_started` 只 `grep` `--tail 40`，`Started` 被挤出窗口 | 改为 `docker logs --since 5m` 再搜 `Started ` |

## 后果

下次 `python pipeline/bin/deploy.py` 会上传 compose/dockerfile。92 上若仍有旧匿名卷，MD5 校验失败时需人上去 `docker volume ls` 清掉对应卷后再 `compose up`。不要把密码写进对话或报告。
