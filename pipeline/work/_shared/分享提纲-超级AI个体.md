# 分享提纲：一人 + AI 做统一 VPN（证据只指向盘上文件）

给 PPT / 申报用。**两条主线并列，不是「产品正文 + 流水线附件」：**

1. **共创选型**：人给约束 → AI 列 2～3 案对比 → 人决策落 ADR（后台若依、否 Web、否 Electron、否桌面 JSON）。
2. **六阶段轨道**：拆解 → 共创 spec → 分域/规范生成 → 门禁 → 回修；证明 AI 被岗位管住，可重复。

凡标「证据」的都能打开核验。不要讲：无人审交整仓、客户端已自动验收、已大规模投产。

已出片（初版）：[分享-超级AI个体-40分钟.pptx](./分享-超级AI个体-40分钟.pptx)（19 页，套《追逐梦想-科技智享》原片，按版式选页，备注里有讲稿）。改页后运行 `python pipeline/work/_shared/build_share_pptx.py` 重生成。

**讲述人：** 一人（后端熟 Java/C++，管理端 Vue 与 Qt 桌面当初都陌生）  
**产品：** GenlotVPN — 同一账号管总部 / 省 / 海外零信任线路，并同步到易安联设备

---

## 0. 一句话

不是「AI 写了个 VPN」，也不是「人选完栈、AI 只写码」。是：

**人给约束 → AI 协助定框架和选型（多案对比）→ 人批 spec → 陌生域先 Demo、熟悉域对照写 → 门禁脚本落盘 → 安全项人验。**

评委若问「AI 到底干了啥」：拆模块、列架构/栈的对比、写 spec、对照写码、跑 gate/deploy/accept、钉钉回修。人干了：认边界、批契约、定 S0、否决 Electron / 明文 HTTP / 升 Boot 3、勾 PHASE2。

## 1. 从需求到「统一 VPN 管理」

**业务（PPT 一页 5 条，来自 SOP，不是事后编的）：**

1. 同一账号登录总部 / 各省 / 海外零信任 VPN  
2. 部门 / 角色 / 用户三级授权  
3. 全链路登录审计与看板  
4. Windows / macOS 都要能用  
5. 多线路统一管理，变更同步到各易安联实例  

**AI 在这一步做什么：** 把口述痛点收成模块表（输入/输出/验收/安全级），人认边界。不让 AI 直接开写。

| 证据 | 路径 |
|------|------|
| 五条目标 + 总模块表（含后来下线的 Web 用户端） | [SOP §5.3](../docs/开发+AI复杂项目六阶段工作法-SOP.md) M01–M08 |
| 当次怎么拆（不要往旧表追加） | [2026-08-15 模块清单](../2026-08-15-用户线路权限查询/模块拆分清单.md)、[2026-08-16 模块清单](../2026-08-16-最低客户端版本拦截/模块拆分清单.md) |
| 硬门槛：未批 spec 不写码 | [pipeline/AGENTS.md](../AGENTS.md) |

**讲法：** 统一管理的「难」不在页面，在**一条本地变更要同步到多台设备、两套 ID 空间**。架构证据是双服务层 + `*YianlianMapping`（见仓库 `CLAUDE.md` / 易安联模块说明），不是 PPT 里新画的。

## 2. AI 怎么协助定框架和选型（前面要讲满）

SOP 阶段二原文：**不要只问「怎么做」，要问「有几种做法，各有什么优缺点」。AI 给建议，人做决策。**

**固定三步（PPT 单独一页）：**

1. **人给约束**：一人、Java 8 / C++、要权限菜单网关、必须 Win+Mac、必须过抓包、30303 不可改。  
2. **AI 列 2～3 案**：模块怎么切、用哪套栈、风险、哪个更贴约束。  
3. **人拍板 + 落盘**：选哪个、为何不选其他、风险怎么接 → ADR / spec。

本项目三次共创（后面各用一页或半页，不要只报「最终选了 X」）：

| 问题 | AI 容易倾向 | 人决策 | 证据 |
|------|-------------|--------|------|
| 管理后台 | 自研完整后台，或顺便升 Boot 3 | 若依 3.6.8，业务只进 yianlian | 仓库模块边界；SOP §6.4 |
| 用户入口 | 先 Web 最快跨平台；桌面推 Electron | 抓包否 Web；否 Electron，取 Qt | SOP M06；ADR-001 |
| 桌面协议 | 复用网关 HTTP JSON | TLS 1.3 + Protobuf :9443 | ADR-002 |

**讲法：** AI 的价值在**把方案铺开、把坑写全**；人的价值在**按约束否决**。没有对比表，看起来像「人选完、AI 打工」。

## 3. 先 Web，再真正的客户端

**当时的想法：** 跨平台最快的是浏览器。先做 VPN **用户端 Web**，Win / Mac 不用出包，验证「统一登录 + 选线」是否成立。

**后来为什么下线：** 登录走网关 HTTP，抓包可见业务；和零信任桌面客户端的安全叙事冲突。网页入口已下线，只留管理端浏览器。

**AI 角度：**

- Web 阶段：AI 把若依登录/菜单套路铺到 VPN 用户页，人验「能不能登上各条线路」。  
- 下线决策：人定（安全），AI 负责**拆走网页入口、改部署文档、别让脚本再指向 8060/8090**。  
- 不是 AI「建议换客户端」就换；是人判定 Web 过不了生产抓包。

| 证据 | 路径 |
|------|------|
| 总表写明 M06 已下线，由 M07 替代 | [SOP 模块表](../docs/开发+AI复杂项目六阶段工作法-SOP.md) |
| 明确不做 Web 端登录 | [PHASE2「不在二期范围」](../../../ruoyi-vpn-client/docs/PHASE2_CHECKLIST.md) |
| 部署：停 vpn-ui / 8060 / 8090，桌面直连 9443 | `docker/README_DEPLOY_3NODES.md` |

**PPT 转折句：** 跨平台的第一解是浏览器；**安全把第一解否决了**，才逼出桌面端。这是架构演进，不是推倒重来玩技术。

## 4. 桌面端：怎么选栈（AI 敢写，人敢否）

**约束：** 一人、更熟 C++、必须 Win+Mac、必须安全、厂商 `127.0.0.1:30303` 不能改。

**AI 会倾向的：** Electron（前端熟、出包快）。  
**人否决的：** Electron 安全面大、非原生，讲不圆「打磨到能用且安全」。WPF 没 Mac。Avalonia 不熟 C#。

**决策：** **Qt 6 + QML**。当时完全陌生，用阶段三：最小 Demo → 人敢做 → 再铺五步法。

| 证据 | 路径 |
|------|------|
| 四选一表 + 否决理由 | [ADR-001](./ADR-001-桌面端技术栈.md) |
| 五步法 MVP → 二期安全/Mac | [PHASE2](../../../ruoyi-vpn-client/docs/PHASE2_CHECKLIST.md) 首段 |
| Mac 已实机可用；签名/公证对外发才做 | PHASE2 Mac-04～06 `[-]` |

**AI 角度：** 陌生域不让 AI 直接生成「整客户端」。先定栈（人），再让 AI 对照已有页长 QML / 编 CMake。传输层单独升 S0，**禁止按熟悉域批量生成**。

## 5. 架构与协议：两张皮，不能图快

**管理端：** 浏览器 → Nginx → 网关 → yianlian（HTTP，若依权限）。  
**桌面端：** 直连 `ruoyi-vpn-auth` **TLS 1.3 + TCP + Protobuf :9443**，不经网页入口。  
**本地隧道：** 仍 HTTP 打 30303（厂商，不可改）。

**AI 会倾向的：** 桌面继续 HTTP JSON，复用网关，出活快。  
**人否决的：** 生产抓包见密码/业务，过不了 S0。

**AI 仍能加速的：** 两端共用 `proto/vpn/*.proto`，改字段同时改 Java 与 C++；管理端查询复用已有授权并集，不新造同步协议。

| 证据 | 路径 |
|------|------|
| 明文 HTTP vs TLS+Protobuf | [ADR-002](./ADR-002-云端协议.md) |
| 契约文件 | `proto/vpn/`（line / auth / envelope） |
| 双服务层：本地库 + 易安联同步 | 仓库架构说明（Controller → `service/vpn` + `service/yianlian`） |

**安全分级（给人看「AI 不是无限权」）：**

| 级 | 谁验 | 例子 |
|----|------|------|
| S0 | 只人 | TLS、证书 Pin、密钥不进日志 |
| S1 | AI 写，人审逻辑 | 登录硬拦 426、多线路同步 |
| S2 | 管理端可 `accept` | 只读查询、策略页文案 |

## 7. 六阶段流水线（第二条主线，要讲细）

这是「超级 AI 个体」能复用的方法，不是产品附录。正式名按 SOP，不要现场发明第七阶段。

| 阶段 | 人 | AI | 准出 |
|------|----|----|------|
| 一 人工拆解 | 认模块边界、熟悉度、安全级 | 收口述为模块表（输入/输出/验收） | 当次目录 + 模块清单 |
| 二 AI 共创设计 | **批准 spec 一次**（硬门槛） | 多案对比、写路径/文案进 spec | 未批不得写业务码 |
| 三 分域突破 | 敢做最小 Demo | 陌生域当即时导师（Vue / Qt） | 能跑的最小切片 |
| 四 规范约束生成 | 抽查对照点 | 按已有 Service / 页面长 | 不另起炉灶 |
| 五 人工质量门禁 | 生产验证码仍开；S0 人验 | `gate → deploy → accept --run` | 写入当次 `质量门禁.md` |
| 六 AI 辅助迭代 | 超 2 轮介入 | 钉钉 + 系统化排错 ≤2 轮 | 再 deploy + accept |

三 / 四按熟悉度分流，不是六步流水账。五不可跳。客户端只编、对照截图，**不进 `accept.py`**。

| 闭环 | 打到哪 | 证据 |
|------|--------|------|
| 2026-08-15 用户线路权限查询 | 管理端只读；回修 2 轮 | [当次目录](../2026-08-15-用户线路权限查询/)、[ADR-003 踩坑](./ADR-003-流水线踩坑.md) |

## 10. 评委可能问，预备答

**「不就是套了若依吗？」**  
若依是共创后取的管理壳：AI 列过自研后台和升 Boot 3，人按一人/Java8 否了。核心是多线路映射、桌面 TLS、以及一人把陌生 Qt 做到 PHASE2 可勾。

**「AI 会不会把密钥写进仓库？」**  
凭证只走本机 `pipeline/deploy/envs.yaml`；Hook 拦疑似密钥。对话和报告用 `***`。

**「为什么客户端不自动验？」**  
S0 不能用页面文案代替抓包。自动验会倒逼关验证码或识图，和自建的红线冲突。
