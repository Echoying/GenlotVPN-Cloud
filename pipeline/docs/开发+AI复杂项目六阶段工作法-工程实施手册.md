## 1. 本手册解决什么问题

主 SOP 回答「分几个阶段、原则是什么」。  
本手册回答 **每天怎么跑、什么叫做完、什么能合入**。

工程化的目标不是把流程写更长，而是让每个模块都满足：

1. **可构建**：本机一条命令能编过  
2. **可验收**：有一句话验收标准，能演示  
3. **可追溯**：选型、门禁、脱敏有落盘记录  
4. **安全可分级**：VPN 认证/证书/密钥与普通 CRUD 不走同一审核深度  

> 核心差异（相对「用 AI 做前后端」）：在 **完全陌生且必须安全** 的领域，把产品打磨到能用。本手册把「能用」写成验收矩阵，把「安全」写成分级门禁。

---

## 2. 工作单元：按模块循环，不按项目瀑布

六阶段不是整项目走完一遍。真正的工作单元是 **一个可独立验收的模块**：

```
选模块（阶段一清单里的一条）
    ↓
熟悉？ ──否──→ 阶段三：最小 Demo → 构建通过
    │
    └─是──→ 阶段四：参照生成 → 构建通过
    ↓
阶段五：按安全分级门禁（不通过回三/四）
    ↓
阶段六：联调 / 跨平台 / 排错
    ↓
合入（commit 注明 AI 参与范围）→ 下一条模块
```

阶段一、二只在项目初期（或架构变更时）串行做一次；之后每个模块都走「三或四 → 五 → 六」。

---

## 3. 安全分级（决定门禁深度）

合入前先给模块定级，**级别由人定，AI 不得自行降级**。

| 级别 | 含义 | 典型模块 | 人与 AI | 门禁 |
|------|------|----------|---------|------|
| **S0** | 出错即安全事故 | 登录/Token、TLS、证书 Pinning、密码/session_key、授权判定 | 人主导设计，AI 只辅助实现与排错 | 必填审核记录；构建 + 安全 Checklist 全过 |
| **S1** | 出错影响业务正确性 | 多线路同步、审计落库、钉钉验证、本地 30303 联调 | AI 可生成，人审逻辑与边界 | Checklist 业务+安全项必勾 |
| **S2** | 常规功能 | 管理端列表页、标准 CRUD、文案/样式 | AI 按参照批量生成 | 构建通过 + 抽查规范/AI 幻觉 |

GenlotVPN 对照：`ruoyi-vpn-client` 传输层、`ruoyi-vpn-auth` TCP/TLS 为 **S0**；用户/部门 CRUD 为 **S2**。

## 4. 各阶段准入 / 准出（Definition of Done）

未满足准出，不得进入下一阶段。允许「先记风险再往下」的，只能是 S2。

### 阶段一：人工拆解

| | 标准 |
|--|------|
| **准入** | 业务目标不超过 5 条；技术约束已知（框架、部署、不能改的厂商接口） |
| **准出** | 模块表填完：技术栈、熟悉度、优先级、依赖、**一句话验收标准**；P0 主链路已标出 |
| **落盘** | 当次目录 `pipeline/work/YYYY-MM-DD-短标题/模块拆分清单.md`（模板见主 SOP 附录 C.1） |
| **人/AI** | 拆什么由人定；AI 只许查漏补缺 |

验收标准必须可演示，禁止「完成前端开发」。  
正确示例：「Win/Mac 均可构建；选线→登录→钉钉→30303→应用列表跑通；生产默认 TLS」。

### 阶段二：AI 共创设计

| | 标准 |
|--|------|
| **准入** | 阶段一清单已完成；本人能力边界已写明 |
| **准出** | 每个关键选型有 **ADR**（至少 2 个备选 + 决策理由 + 否决原因）；数据模型/主链路接口已确认 |
| **落盘** | 跨功能 `pipeline/work/_shared/ADR-xxx.md`；仅当次的写进当次目录 |
| **人/AI** | AI 出 2～3 案并对比风险；人签字决策。方案可推倒重来 |

**ADR 必填字段：**

```markdown
# ADR-00x：[决策标题]
- 日期 / 状态：已采纳 | 已废止
- 背景约束：（原生 / 跨平台 / 更熟 C++ / 必须安全 / 厂商 30303 不可改 …）
- 备选方案：A / B / C（各写优缺点与风险）
- 决策：选 [X]
- 否决：[Y] 的原因
- 安全影响：是否升为 S0/S1
- 复验方式：如何证明决策落地
```

GenlotVPN 实例（应落盘，勿只留在聊天里）：

| ADR | 决策 | 否决 |
|-----|------|------|
| 桌面端技术栈 | Qt 6 + QML（熟 C++、Win/Mac 一套 UI） | Electron（非原生）；WPF（难跨 Mac）；Avalonia（不熟 C#） |
| 云端协议 | TLS 1.3 + TCP + Protobuf，端口 9443 | 桌面端继续走 HTTP JSON |
| 本地控制器 | 保持 HTTP `127.0.0.1:30303` | 厂商 API 改为 Protobuf |

### 阶段三：分域突破（陌生域）

| | 标准 |
|--|------|
| **准入** | 模块标为「陌生」；验收标准已写成可验证语句 |
| **准出** | ① 最小 Demo **构建通过** ② 开发者能讲清目录与主路径 ③ 有分域突破记录（学了什么、坑、耗时） |
| **落盘** | 当次目录下 `分域突破-模块名.md` + 可复用构建脚本 |
| **节奏** | 每次只加一个功能点，加完立刻构建；禁止一次生成整个客户端 |

推荐节奏（客户端类）：

1. 空窗口 / 空服务启动  
2. 本机构建脚本固化（`bin/build-*.bat` 或 CMake 预设）  
3. 打通一条主链路（如只登录）  
4. 再叠选线、验证码、本地控制器  
5. 最后才做 TLS / Pinning / 打包  

恐惧靠「下一步小到能验证」消除，不靠先系统学完。

### 阶段四：规范约束生成（熟悉域）

| | 标准 |
|--|------|
| **准入** | 有参照模块路径；目标文件路径已写死 |
| **准出** | 生成范围仅限声明文件；命名/分层与参照一致；构建通过 |
| **落盘** | Prompt 原文可附在 PR/提交说明，或收入附录 B |
| **禁止** | 不给参照、一次生成整层、让 AI 改无关文件 |

### 阶段五：人工质量门禁

| | 标准 |
|--|------|
| **准入** | 本模块构建已通过（编译失败不得进入人工审） |
| **准出** | 按级别勾完 Checklist；S0 必须有审核记录行 |
| **落盘** | 当次 `质量门禁.md` + 总表 `pipeline/work/_shared/质量门禁记录.md`（主 SOP 附录 C.3） |
| **否决** | 日志打印密码/Token/session_key；硬编码密钥；S0 无记录仍合入 |

门禁顺序固定：**先构建，再结构/命名，再业务，最后安全**。  
S0 额外必验（VPN 客户端）：

- [ ] 生产默认 TLS，无明文 TCP fallback  
- [ ] 证书 Pin 错误时拒绝连接  
- [ ] 密码/Token/session_key 不落盘明文、不进日志  
- [ ] 向 AI 的对话已脱敏  

### 阶段六：AI 辅助迭代

| | 标准 |
|--|------|
| **准入** | 问题可复现；已收集现象、完整日志、相关片段、已尝试、环境 |
| **准出** | 原问题关闭；回归主链路；典型坑写入案例库 |
| **跨平台** | 改传输/打包/路径时，Win 与 Mac **各验一次**（能验的平台都要验） |

## 5. 上下文包（每次问 AI 的最低输入）

不满足下列输入，视为无效提问，应先补齐再生成。

| 必带 | 说明 | GenlotVPN 示例 |
|------|------|----------------|
| 约束 | 框架版本、不能改的接口 | Spring Boot 2.7 / Qt 6 / 30303 保持 HTTP |
| 参照 | 文件路径或粘贴关键片段 | `system/user/index.vue`；已有 `TcpClient` |
| 范围 | 只改哪些文件 | `src/transport/CertificatePinner.cpp` |
| 验收 | 做完如何验证 | `windeployqt` 后干净机可启动；Pin 错误断开 |
| 安全级 | S0/S1/S2 | 传输层 = S0 |
| 脱敏 | 无密码、密钥、生产地址中的密钥材料 | 用占位符 `***` |

仓库级长期上下文（减少重复粘贴）：`CLAUDE.md`、模块 README、本手册、主 SOP 附录 B。

## 6. 构建即门禁（命令清单）

人工审核之前，对应技术域必须绿。命令按仓库现状选用，失败则回阶段三/四。

| 域 | 验证命令（示例） | 通过标准 |
|----|------------------|----------|
| Java 模块 | `mvn clean package -pl <模块> -am -DskipTests`（需 JDK8） | 编译成功；主版本号 52 |
| 管理端 | `cd ruoyi-ui && npm run dev` 或 `build:prod` | 页面可开，接口代理正确 |
| 桌面客户端 | `bin\build-vpn-client.bat` / CMake + `windeployqt` | exe 能起；干净机缺 DLL 则未过 |
| 协议 | proto 生成 Java/C++ 后两端字段对齐 | 同一套 `.proto`，无手写分叉 |
| 安全回归 | 对照 `ruoyi-vpn-client/docs/PHASE2_CHECKLIST.md` 的 S-xx | TLS/Pin/限流等 P0 项可勾 |

「能用」不是页面出来，而是 **目标平台上主链路可演示**。

## 7. 「能用」验收矩阵（交付门槛）

模块或版本宣称「能用」时，按下表勾选。S0 相关行未勾，不得对外说已完成。

| 编号 | 项 | 通过标准 | 级别 |
|------|----|----------|------|
| U1 | 主链路 | 选线 → 登录 → 钉钉 → 本地控制器 → 应用列表 | S1 |
| U2 | Windows | 可构建、可启动、可走完 U1 | S1 |
| U3 | macOS | 可构建、可启动、可走完 U1（有 Agent 时） | S1 |
| U4 | 生产传输 | 默认 TLS；抓包无明文密码/JSON 业务载荷 | S0 |
| U5 | 证书 | Pin 错误拒绝；轮换窗口有备用 Pin（如已做） | S0 |
| U6 | 凭据 | 记住密码走 DPAPI/Keychain；日志无密钥 | S0 |
| U7 | 打包 | 干净机器能装能开（文档见 DEPLOY_WINDOWS / DEPLOY_MACOS） | S1 |
| U8 | Web 不受损 | 管理端 HTTP 流程仍可用（双协议并存时） | S1 |

## 8. 合入约定

| 项 | 要求 |
|----|------|
| 提交说明 | 写清改了什么、如何验证；S0 注明「已按阶段五审核」 |
| AI 范围 | 一句即可：如「AI 生成初稿，传输层 HMAC 逻辑人工改写」 |
| 禁止 | 跳过构建直接合入；S0 无门禁记录；把未脱敏对话贴进仓库 |
| 文档同步 | 行为或配置变了，同步更新对应 `docs/` 或 Nacos 示例 |

## 10. 每日/每周最小闭环

**每日（做某一个模块时）**

1. 打开清单上的一条，确认熟悉度与安全级  
2. 按上下文包提问，只改声明范围内的文件  
3. 构建  
4. S0/S1 过门禁再合入  
5. 坑记一条（可选，典型问题必记）

**每周**

1. 对照「能用」矩阵看主链路是否回退  
2. 架构若有否决/改选，补一条 ADR  
3. 更新 Checklist 状态（`[x]` / `[~]` / `[ ]`）

## 11. 与主 SOP、申报材料的关系

| 材料 | 用途 |
|------|------|
| 主 SOP | 原则、阶段说明、Prompt、评分叙事中的「方法名称」 |
| 本手册 | 可执行的准入准出、安全分级、构建门禁、验收矩阵 |
| 仓库实施说明 | 六阶段如何接到本仓 skill / Rule / 脚本；如何演示 |
| 仓库 pipeline/work + 客户端 Checklist | 评委要的「可核验沉淀」，不是聊天截图 |

一票否决相关：S0 未经人审合入、向 AI 上传未脱敏密钥，视为违反主 SOP 第 12 章与本手册第 5、8 节。
