## 4. 必须改的嫁接点

入口文件名保持 `gate.py` / `deploy.py` / `accept.py`，评委和 Agent 才认同一套命令。改的是**里面调什么**。

### 4.1 `pipeline/bin/gate.py`

本仓写死了：JDK8 + `mvn clean package`、`ruoyi-ui` 的 `npm run build:prod`、桌面客户端打包。

新项目按栈改 `build_java` / `build_ui` / `build_client`（或删掉没有的端）。命令行用法尽量保留：

```bash
python -u pipeline/bin/gate.py server --run <当次>
python -u pipeline/bin/gate.py --run <当次>          # 全量
```

没有桌面端：默认 `gate` 不要编客户端，`AGENTS.md` 删掉「客户端要编、不自动验收」里与本仓 Qt 相关的句子，改成新项目的 S0。

### 4.2 `pipeline/bin/deploy.py` → `work/bin`

本仓 `deploy.py` **写死** `from deploy_admin_92 import main`。新项目两种接法，选一种：

- **快**：在 `pipeline/work/bin/` 仍放名为 `deploy_admin_92.py` 的适配器，里面改成新项目的发布（主机、目录、服务名）。入口命令不用改。
- **干净**：改 `deploy.py` 为 `from deploy_impl import main`，新文件叫 `deploy_impl.py`。

`deploy.py vpn` 在本仓表示再部 93 vpn-auth。新项目没有对等物就不要提供 `vpn`，或改成新项目的第二台机。

### 4.3 `pipeline/bin/accept.py` → `work/bin`

本仓默认 `from accept_admin import main`；`accept.py client-ref` 走 `accept_client_ref.py`。

新项目：

- 有浏览器管理端：重写 `accept_admin.py`（base_url、账号、选择器、断言点 spec 里的路径/文案）。
- 没有页面、只有构建：`accept.py` 可以先做成「检查产物存在 + 写报告」，不要假装 Playwright 过了。
- 没有桌面端：不要提供 `client-ref`，或进命令就打印「本项目无客户端走查」并退出 0。

### 4.4 `pipeline/deploy/envs.yaml.example`

改成新项目的键：SSH 主机、远程目录、验收 URL、账号占位。**值留空**。钉钉仍只填 `access_token` 段，不要整段 webhook。

### 4.5 `pipeline/AGENTS.md` 与 Rule

必改：标题里的项目名、S0/S1/S2 例子、PHASE2 路径（没有就删）、`deploy.py vpn` 是否还存在。  
不改：未批 spec 不写码、`gate → deploy → accept` 必须带 `--run`、回修 ≤2、凭证不入库。

`java-modules` / `ruoyi-ui` / `qt-client` 三条 Rule：新项目不是这套栈就不要拷到 `.cursor/rules/`。

## 5. 搬迁命令（在本机执行）

下面把 `SRC` 换成本仓根，`DST` 换成目标仓根。在 PowerShell 里跑。

```powershell
$SRC = "D:\cursor\genlot\GenlotVPN-Cloud"
$DST = "D:\cursor\<新项目根>"

# 1. 骨架
New-Item -ItemType Directory -Force -Path "$DST\pipeline" | Out-Null
Copy-Item "$SRC\pipeline\README.md","$SRC\pipeline\AGENTS.md","$SRC\pipeline\六阶段流水线-Agent执行指引.md" "$DST\pipeline\"
Copy-Item "$SRC\pipeline\docs" "$DST\pipeline\docs" -Recurse -Force
Copy-Item "$SRC\pipeline\bin" "$DST\pipeline\bin" -Recurse -Force
Copy-Item "$SRC\pipeline\cursor" "$DST\pipeline\cursor" -Recurse -Force
Copy-Item "$SRC\pipeline\deploy" "$DST\pipeline\deploy" -Recurse -Force

# 2. 不要带进 pyc / 本仓当次 / 填好的凭证
Get-ChildItem "$DST\pipeline" -Recurse -Filter "__pycache__" | Remove-Item -Recurse -Force
Remove-Item "$DST\pipeline\deploy\envs.yaml" -ErrorAction SilentlyContinue

# 3. work 只留空壳
New-Item -ItemType Directory -Force -Path "$DST\pipeline\work\bin","$DST\pipeline\work\_shared" | Out-Null
```

`work/bin` 先放三个空适配器（名称与本仓入口一致，便于 `deploy.py` / `accept.py` 不用先改）：

- `deploy_admin_92.py`：实现新项目的发布，或先 `raise SystemExit("尚未接入部署")`
- `accept_admin.py`：实现新项目的页面/产物验收，或同样先失败并说明
- 不要拷 `apply_sql_91.py`、`accept_client_ref.py`、`upload_and_extract_docker.py`，除非新项目真有对等物

`_shared` 最小文件：

```markdown
# _shared
跨功能 ADR、门禁总表放这里。不要把某次 spec / 截图放进来。
```

```markdown
# AI 生成代码质量门禁审核记录

| 日期 | 当次目录 | 模块 | 回修轮次 | 结果 |
|------|----------|------|----------|------|
```

根指针：

```powershell
# 薄 AGENTS.md：内容与本仓根 AGENTS.md 同类，改成指向 pipeline/AGENTS.md
Copy-Item "$SRC\AGENTS.md" "$DST\AGENTS.md"

New-Item -ItemType Directory -Force -Path "$DST\.cursor\rules" | Out-Null
Copy-Item "$SRC\pipeline\cursor\rules\ai-pipeline.mdc","$SRC\pipeline\cursor\rules\s0-security.mdc" "$DST\.cursor\rules\"
Copy-Item "$SRC\.cursor\hooks.json" "$DST\.cursor\hooks.json"
```

然后在目标仓：

1. 改 `pipeline/AGENTS.md`、`gate.py` 构建命令、`envs.yaml.example`。  
2. 实现或占位 `work/bin` 两个适配器。  
3. `.gitignore` 加上 `pipeline/deploy/envs.yaml`、`.deploy/`、`.env`。  
4. 复制 example 为 `pipeline/deploy/envs.yaml`，只在本机填。  
5. 挂 skill：与本仓一样用 skillshare 指到 echoying-skills，**不要**把六阶段再抄进目标仓的 skill 目录。

```powershell
cd $DST
pip install -r pipeline/bin/requirements-admin-e2e.txt
# 有管理端 Playwright 验收时：
playwright install chromium
```

## 6. 嫁接后怎么跑（与本仓同一套命令）

凭证只走本机 yaml 或环境变量。当次名：`YYYY-MM-DD-短标题`，不要斜杠。

### 6.1 阶段一 / 二（先有目录，再写码）

在目标仓打开 Cursor，对 Agent 说清：走六阶段，当次目录建在 `pipeline/work/`。

人要认的：

- `pipeline/work/<当次>/模块拆分清单.md`
- `pipeline/work/<当次>/spec.md`（路径、按钮、文案写死；第 7 节写可复制命令）

**spec 未批，不得写业务码。**

### 6.2 阶段五（命令与本仓相同，参数来自新 spec 第 7 节）

在**目标仓根**执行：

```bash
python -u pipeline/bin/gate.py server --run <YYYY-MM-DD-短标题>
python -u pipeline/bin/deploy.py --run <YYYY-MM-DD-短标题>
python -u pipeline/bin/accept.py --run <YYYY-MM-DD-短标题> --path <spec路由> --expect-text <spec文案> --module <编号> --round 0
```

有全量构建时用 `gate.py --run <当次>`（不要默认再编本仓的 Qt，除非你在 `gate.py` 里接上了）。

部署范围若仍用本仓子命令：

```bash
python -u pipeline/bin/deploy.py ui --run <当次>
python -u pipeline/bin/deploy.py vpn --run <当次>
```

新项目没接 `vpn` 就不要跑。

钉钉（无 token 会 skip，退出码 0）：

```bash
python -u pipeline/bin/notify.py markdown "标题" --text-file pipeline/work/<当次>/验收报告/验收报告-YYYY-MM-DD.md
```

`--run` 必须带。结果要出现在当次 `质量门禁.md` 的脚本记录里，否则不得声称已门禁。

### 6.3 阶段六

页面失败：钉钉发缺陷 → `_systematic-debugging` → 再 `deploy` + `accept`，最多 2 轮。超轮次停下来等人。需求理解错了才回阶段二。

### 6.4 建议的第一条（用来证明「迁成功」）

不要一上来迁一条 S0。选管理端只读或一次构建可断言的小需求：

1. 建 `pipeline/work/YYYY-MM-DD-短标题/`  
2. 人批 spec  
3. `gate.py server --run <当次>` 能在新栈上过  
4. 若已接部署/验收：再跑 `deploy` / `accept`  
5. 总表 `pipeline/work/_shared/质量门禁记录.md` 记一行  

这一行才是「已迁到另一仓」的证据。只拷文件、没跑过 `--run`，申报里不要那么写。

**状态（2026-08-18）：** 讲述人确认，已迁到其他项目并完成验证。本仓保留搬迁步骤；核验时打开**目标仓** `pipeline/work/<当次>/` 的 `质量门禁.md`（须有 `--run` 脚本记录）。仍不写「已大规模铺开」。

## 8. 和本仓的差异（写给改脚本的人）

| 本仓事实 | 迁走时 |
|----------|--------|
| `gate` 编 Java 全量 + ruoyi-ui + 客户端 | 改成新项目的构建；没有的端删掉 |
| `deploy` 转发 `deploy_admin_92` | 换实现或换 import |
| `accept` 转发 `accept_admin` / `client-ref` | 换选择器或先做产物检查 |
| S0 = TLS / Pin / PHASE2 | 重新定义新项目的「只人验」 |
| 管理端可关 92 验证码做 E2E | 生产仍保持开；新环境怎么关写进新仓实施说明，不要抄 92 地址 |

对话、提交、文档仍然禁止写密码、私钥、钉钉 token、SSH 密码。
